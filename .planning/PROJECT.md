# Surypus ERP

## What This Is

Surypus — ERP-система на Haskell: товары и склад, счета, двойная бухгалтерия, НДС и отчётность. Сейчас это большая кодовая база с частично реализованным доменом и множеством заглушек: сервер не стартует, часть сервисов возвращает фиктивные результаты. Цель текущего этапа — довести систему до рабочего состояния: один сквозной путь от товара до проводок и остатка, работающий на реальном PostgreSQL.

## Core Value

Пользователь может провести реальную хозяйственную операцию — принять товар, выставить счёт, оплатить его и увидеть корректные проводки и остаток — на работающем сервере с настоящей базой данных.

### Out of Scope

- Зарплата и кадры — не нужны для доказательства работоспособности основного контура
- Отчётность и экспорт (PDF/Excel) — отдельный слой над уже корректными данными
- GraphQL-шим, WebSocket, Kafka/EventBridge — вторичные интеграции, сначала HTTP + БД
- Redis-очереди и in-memory job runner — заменяются одним каноном на PostgreSQL
- Мобильный клиент и любые не-Haskell UI-фреймворки — ограничение языка проекта
- Аутентификация внешних провайдеров (OAuth/LDAP) — только локальные пользователи и роли

## Context

**Состояние кодовой базы** (полная карта: `.planning/codebase/`):

- `app/Main.hs` — заглушка на 7 строк, API-сервер не запускается; Docker-образ стартует и сразу завершается.
- 181 маркер `stub`/`placeholder`/`Phase 1:` в `src/`; часть модулей экспортируется и вызывается, но ничего не делает.
- Дублирование домена: два `Decimal`, два VAT-движка с разными единицами ставки (доли vs проценты — ошибка в 100×), семь реализаций двойной записи, три типа `Stock`, четыре очереди задач.
- `DAL.Repository.RBAC.checkUserAppPermissionRepo` всегда возвращает `True` — потенциальный обход авторизации.
- `DAL.DB` — in-memory база с фейковыми данными, всё ещё импортируется в `Service/BillService.hs`.
- Тесты: Hspec + QuickCheck, 80% coverage gate, `DAL.EventStoreSpec` не подключён в `other-modules`.
- Документация: Haddock плотный (~1 967 строк), doctest заявлен политикой, но примеров `>>>` нет и в CI он не подключён.

**Подход:** консолидация вместо нового слоя поверх старого. Для каждого домена выбирается один канонический модуль, дубли удаляются сразу (история остаётся в git), затем канон подключается к сквозному пути. Порядок работ — от запуска сервера к деньгам, затем учёт, затем UI и RBAC.

## Constraints

- **Язык**: Haskell (Haskell2010) — другие языки только по явному согласованию (AGENTS.md)
- **БД**: реальный PostgreSQL, миграции в `config/migrations/`, схема как источник истины
- **Деньги**: `Data.Decimal` с фиксированной точностью; `Double` для денег запрещён
- **Верификация**: инвариант баланса проводки обязателен к доказательству в v1 (LiquidHaskell/refinement-типы)
- **UI**: серверный рендеринг на Haskell + HTMX, без отдельного JS-фреймворка
- **Приёмка**: автотесты + короткий ручной smoke-чеклист на каждом фазовом переходе
- **Совместимость**: существующие миграции и доменные типы сохраняются, ломающие изменения схемы — только через новую миграцию

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| v1 = один сквозной путь, а не «починить всё» | Даёт проверяемый результат и естественный порядок работ | — Pending |
| Консолидировать дубли сразу, а не замораживать | Две единицы НДС и три типа остатка делают любые расчёты неоднозначными | — Pending |
| Канон учёта: `Finance.Types` + `DAL` | Чистые инварианты отдельно от записи; проще доказать баланс | — Pending |
| Деньги: `Data.Decimal` | Фиксированная точность, отсутствие дрейфа округления | — Pending |
| НДС: явные `RatePercent` / `RateFraction` | Устраняет ошибку в 100× на границе модулей | — Pending |
| Очередь: `DAL.Queue` на PostgreSQL | Один источник истины для retry/статусов, без Redis | — Pending |
| UI: серверный Haskell + HTMX | Укладывается в ограничение «только Haskell» | — Pending |
| RBAC: `admin` / `accountant` / `storekeeper` | Минимально достаточно для сквозного пути и реальных проверок | — Pending |
| Верификация баланса обязательна в v1 | Это главный инвариант бухгалтерии; позже он дороже | — Pending |
| Удалять проигравшие модули сразу | Иначе дубли продолжают использоваться и расходятся | — Pending |
